# CurseForge → Telegram: бот новых аддонов WoW

Дата: 2026-10-24

## Цель

Бот следит за появлением **новых** аддонов World of Warcraft на CurseForge и публикует
каждый в один Telegram-канал/чат: название, автор, категории, поддерживаемые версии игры
(Retail / Classic / Forever), краткое описание, ссылка и картинки (логотип + скриншоты).

Не входит в задачу: уведомления об обновлениях существующих аддонов, подписки отдельных
пользователей, приём команд от пользователей, уведомления о том, что у аддона позже
появилась поддержка новой версии игры.

## Решения

| Вопрос | Решение |
|---|---|
| Версии игры | Метки в каждом сообщении + фильтр в конфиге |
| Получатели | Один канал/чат, задаётся `TELEGRAM_CHAT_ID` |
| Хостинг | VPS / домашний сервер, постоянный процесс (Docker или systemd) |
| Формат | Альбом: логотип + до 3 скриншотов, подпись на первой картинке |
| Определение «нового» | Поиск, отсортированный по дате выхода (`dateReleased`), сравнение с виденными id |
| Поздняя поддержка версий | Не отслеживается: метки и фильтр — на момент выхода аддона |

## Источник данных: CurseForge API

- Базовый URL `https://api.curseforge.com`, ключ в заголовке `x-api-key`
  (выдаётся на console.curseforge.com).
- WoW: `gameId=1` (проверить через `GET /v1/games`).
- Раздел «Addons»: `classId` берётся из `GET /v1/categories?gameId=1&classesOnly=true`.
- Типы версий: `GET /v1/games/1/version-types` (пример: 517 = `wow_retail`).
- Новые аддоны: `GET /v1/mods/search?gameId=1&classId=<Addons>&sortField=<ReleasedDate>&sortOrder=desc&pageSize=50`.
- Используемые поля мода: `id`, `name`, `summary`, `links.websiteUrl`, `authors[].name`,
  `categories[].name`, `logo.url`, `screenshots[].url`, `dateReleased`,
  `latestFilesIndexes[].gameVersionTypeId`.

**Проверить живым запросом до написания кода (первая задача реализации):**
1. Числовое значение `ModsSearchSortField` для сортировки по дате выхода (ожидается `11`).
   Если такой сортировки нет — запасной вариант B: `LastUpdated` (3) + фильтр
   `dateReleased > время прошлой проверки`.
2. Как в `version-types` представлен WoW Forever (отдельный тип или нет; на 2026-10
   его аддоны на сайте помечены версией клиента `1.60.1`, бета). Если Forever нельзя
   отличить по типу версии — остановиться и согласовать с пользователем.
3. `gameId` WoW и `classId` раздела Addons.

## Структура

```
curse_bot/
  bot/
    config.py      — настройки из окружения (.env)
    curseforge.py  — HTTP-клиент CurseForge: search, version-types, classes
    flavors.py     — gameVersionTypeId → группа/метка, фильтр (чистые функции)
    storage.py     — SQLite: виденные id
    formatter.py   — подпись и выбор картинок (чистые функции)
    telegram.py    — отправка в Bot API с fallback и обработкой 429
    main.py        — цикл опроса, CLI-флаги
  tests/
  Dockerfile, docker-compose.yml, .env.example, README.md
```

Стек: Python 3.12, `httpx`, `sqlite3` из стандартной библиотеки, `pytest`.
Telegram Bot API вызывается напрямую через `httpx`, без фреймворка.

## Конфигурация

| Переменная | Обязательна | По умолчанию | Смысл |
|---|---|---|---|
| `CURSEFORGE_API_KEY` | да | — | ключ CurseForge |
| `TELEGRAM_BOT_TOKEN` | да | — | токен бота |
| `TELEGRAM_CHAT_ID` | да | — | канал/чат (бот должен быть админом канала) |
| `FLAVORS` | нет | пусто = все | список групп через запятую: `retail,classic,forever` |
| `POLL_INTERVAL` | нет | `600` | секунды между циклами |
| `DB_PATH` | нет | `data/bot.db` | путь к SQLite |

Неизвестное значение в `FLAVORS` или отсутствие обязательной переменной — ошибка при старте.

## Версии игры (flavors.py)

На старте загружаются типы версий и раскладываются по группам:

- **Retail** — `wow_retail`;
- **Classic** — все Classic-типы (Era, TBC, Wrath, Cata, MoP Classic и т.п.);
- **Forever** — тип, в имени/slug которого есть «forever».

Метка в сообщении: группы через ` · `, у Classic в скобках конкретные версии:
`Retail · Classic (Era, MoP) · Forever`. Тип, не попавший ни в одну группу,
показывается под своим именем API и логируется как `unknown version type`; фильтр
`FLAVORS` его не пропускает, если фильтр задан. Аддон проходит фильтр, если хотя бы одна
его группа есть в `FLAVORS`.

## Поток данных

**Первый запуск** (таблица виденных пуста): текущая первая страница поиска сохраняется
как виденная, ничего не отправляется, в лог — `baseline: N addons`.

**Флаг `--send-latest N`**: разово отправить N последних аддонов (для проверки)
и завершиться; виденными их не помечать.

**Цикл:**
1. `search` (50 штук по убыванию даты выхода).
2. Новые = id, которых нет в базе; порядок отправки — от старых к новым.
3. Для каждого нового:
   - вычислить группы версий;
   - не прошёл `FLAVORS` → пометить виденным, не отправлять;
   - иначе отправить; пометить виденным **только после успешной отправки**.
4. Пауза ~3 с между сообщениями, затем сон `POLL_INTERVAL`.

## Сообщение (formatter.py, telegram.py)

Картинки: `logo.url` + первые 3 `screenshots[].url` (полный размер, не thumbnail),
без дублей, максимум 4.

- ≥2 картинки → `sendMediaGroup`, подпись на первой;
- 1 картинка → `sendPhoto`;
- 0 картинок → `sendMessage`.

Подпись (`parse_mode=HTML`, не длиннее 1024 символов; для `sendMessage` тот же текст):

```
🆕 <b>Название</b>
👤 Автор1, Автор2 · 📂 Категория1, Категория2
🎮 Retail · Classic (Era, MoP) · Forever

summary

🔗 https://www.curseforge.com/wow/addons/slug
```

Все поля из API экранируются (`html.escape`). При превышении лимита обрезается только
`summary` (с `…`), остальные строки сохраняются.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| CurseForge: сеть, таймаут, 5xx | лог, пропуск цикла; база не меняется |
| CurseForge: 403 | лог «неверный или отозванный API-ключ», процесс продолжает работу |
| Telegram: 429 | ждать `retry_after`, повторить (до 3 раз) |
| Telegram: ошибка альбома (картинка не скачалась и т.п.) | fallback: `sendPhoto` с логотипом → `sendMessage` |
| Telegram: прочие ошибки (неверный chat_id и т.п.) | лог, аддон не помечается виденным, повтор в следующем цикле |
| Падение процесса | перезапуск Docker (`restart: unless-stopped`) / systemd; состояние в SQLite |

Логи — stdout, с временем и уровнем.

## Тестирование (pytest)

- `flavors`: раскладка типов по группам на сохранённом реальном ответе `version-types`;
  фильтр; формат метки; неизвестный тип.
- `formatter`: экранирование, обрезка до 1024, выбор картинок (лого + 3 скрина,
  без скринов, без лого, дубль лого среди скринов).
- `storage`: пустая база, пометка, «новые = невиденные».
- `main` (с фейковыми клиентами): первый запуск ничего не шлёт; новый аддон отправляется;
  отфильтрованный помечается без отправки; при ошибке Telegram аддон повторяется
  в следующем цикле; порядок от старых к новым.
- Ручная проверка: живой прогон `--send-latest 2` в чат пользователя.
